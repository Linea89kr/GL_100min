무한의 오답 협동조합 아키텍처

단일 HTML 한 장이 Supabase에 직접 붙고, 키가 필요한 일(LLM 판정·해설, 판정 뒤집기)만 Vercel 서버리스 함수가 맡는 구조입니다. 기획서 ADR-001의 Option A를 그대로 구현했습니다.

index.html · 바닐라 JS Supabase · Postgres + Realtime Vercel Functions × 4 Gemini 2.5 Flash / Flash-Lite

시스템 구성도

브라우저는 anon key로 DB를 직접 읽고 씁니다. 판정 결과 쓰기처럼 권한이 필요한 작업은 service_role key를 가진 함수만 할 수 있고, RLS가 그 경계를 지킵니다.

레포 지도

브라우저에서 실행 Vercel 서버리스 DB 문서·참고
  • index.htmlclient게임 본체. 참가자·호스트·큰 화면·위키 4개 뷰를 URL 파라미터로 나눔Supabase JS(CDN)로 직접 조회·삽입, Realtime 구독, 판정·해설은 /api 호출. 상단 상수 SUPABASE_URL / SUPABASE_ANON_KEY
  • api/edgeVercel이 파일마다 서버리스 함수로 배포
  • _lib.js공용 유틸. 이름이 _로 시작해 라우트로 노출되지 않음환경변수 별칭 처리(pickEnv), service_role 클라이언트(admin), gemini() REST 호출, 모델 설정
  • config.jsGET 브라우저에 URL·anon key 전달found 필드로 어떤 변수 이름을 찾았는지 진단(값은 노출 안 함)
  • judge.jsPOST {answer_id} 실수로 정답인지 판정 → verdict, closeness, misconception정답·동치 표현과 글자가 같으면 LLM 없이 🎯. 아니면 gemini-2.5-flash-lite + JSON 스키마
  • explain.jsPOST {question_id} 가장 많이 속인 오답 3개로 해설 → questions.explanationgemini-2.5-flash. [정답] / [오답N] / [팁] 형식
  • override.jsPOST {answer_id, verdict} 호스트의 판정 뒤집기answers는 anon update 금지라 서버에서 처리
  • supabase/schema.sqldb테이블 5개 + answer_scores 뷰 + RLS + Realtime publicationSQL Editor에 붙여넣고 Run. 여러 번 실행해도 안전
  • package.jsonedge서버리스 의존성: @supabase/supabase-js 하나
  • .env.exampledocVercel에 넣을 환경변수 목록(값 없음)
  • code_artifact.htmldoc초기 UI 목업. 로컬 상태로만 동작하는 참고본
  • template/doc참가자 배포용 해커톤 템플릿(Copilot 생성, 60초 클릭 게임)
  • wrong-answer-coop-기획서.mddoc기획 · ADR · 스키마 원본

오답 하나가 지나가는 길

제출은 즉시 화면에 뜨고, 판정은 뒤에서 2~3초 걸려 도착합니다. 판정을 기다렸다가 보여주면 분위기가 식기 때문에 비동기로 나눴습니다.

라운드 단계

모든 화면은 questions.phase 한 컬럼만 봅니다. 호스트가 이 값을 바꾸면 Realtime으로 참가자와 큰 화면이 함께 넘어갑니다.

phaseDB에 일어나는 일
openends_at = 지금 + 60초. answers insert 허용
closed제출 차단. 호스트가 판정 검토
bluff정답(0) + 그럴듯한 오답 3개를 섞어 bluff_answer_ids에 저장. votes insert 허용
revealed/api/explain 호출 → explanation 저장. 두 트랙 시상

데이터 모델과 권한

anon key는 공개돼도 되는 키라 레포나 브라우저에 있어도 괜찮습니다. 대신 각 테이블의 RLS가 "누가 무엇을 쓸 수 있는지"를 정합니다.

rooms 방

  • id text PK · 'ABC1'
  • name
anon: 읽기 · 생성

questions 라운드

  • id · room_id → rooms
  • prompt · answer · accepted_variants[]
  • phase · explanation
  • bluff_answer_ids bigint[]
  • ends_at timestamptz
anon: 읽기 · 생성 · 수정 (MVP, room 코드가 사실상 비밀)

answers 오답

  • id · question_id → questions
  • device_id · nickname · body
  • verdict · closeness · misconception
  • host_override
anon: 읽기, open 단계에서 pending으로만 생성. 수정은 service_role만

reactions 이모지

  • PK (answer_id, device_id, emoji)
  • emoji ∈ 😂 🤔 💀 📚
anon: 읽기 · 생성. PK로 같은 반응 중복 방지

votes 블러프 투표

  • PK (question_id, device_id)
  • picked_answer_id · null이면 진짜 정답 선택
anon: 읽기, bluff 단계에서만 생성. 1인 1표

answer_scores 뷰

  • answers + laughs · reactions · fooled
해설 생성(상위 오답 3개)과 위키 카드에 사용

환경변수

Vercel → Settings → Environment Variables에 넣고 Redeploy해야 적용됩니다. /api/config를 열면 어떤 이름을 찾았는지 확인할 수 있습니다.

이름읽는 곳공개 여부함께 인식하는 이름
SUPABASE_URLconfig, 모든 함수공개NEXT_PUBLIC_SUPABASE_URL
SUPABASE_ANON_KEYconfig → 브라우저공개 (RLS가 방어)NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_PUBLISHABLE_KEY
SUPABASE_SERVICE_ROLE_KEYjudge, explain, override비공개. 서버에만SUPABASE_SECRET_KEY
GEMINI_API_KEYjudge, explain비공개. 서버에만GOOGLE_API_KEY, GOOGLE_GENERATIVE_AI_API_KEY
GEMINI_MODEL_JUDGEjudge선택기본 gemini-2.5-flash-lite
GEMINI_MODEL_EXPLAINexplain선택기본 gemini-2.5-flash

알려진 한계와 다음 단계

  • 호스트 인증 없음. &host=1만 붙이면 누구나 호스트입니다.
  • 정답이 읽힘. questions.answer를 anon이 읽을 수 있어 개발자도구로 볼 수 있습니다.
  • LLM 장애 시 카드가 "AI 판정 중"에 머뭅니다. 호스트가 직접 판정해야 합니다.
  • Realtime이 꺼져 있으면 새로고침해야 갱신됩니다. 4초 폴링 보완은 PR #6에 있고 아직 머지 전입니다.
  • 정답 컬럼을 분리하고, 공개 시점에만 RPC로 내려주기
  • 방 생성 시 host token 발급, questions 쓰기를 토큰으로 제한
  • 위키 상세 페이지와 명예의 전당
  • 위키가 커지면 Next.js로 이전 (ADR-002)
